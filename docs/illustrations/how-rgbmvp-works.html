How this repository works

One API. Stickers off-chain.
Boxes on two chains.

The browser is a thin console. The CLI and labd share the same /v1 JSON. Keys never enter the browser. RGB history lives in envelopes. Bitcoin and Liquid only see a sealed box and a 32-byte stamp.

1 · Surfaces — same validation, different jobs

No keys

Wallets, consignments, HTLC driver. Operator machine. Public mutations need a token. Demo swaps are flag-gated.

2 · RGB layer — the sticker book

R0 ISSUE
Make a contract

Genesis is glued to one chain. Liquid RGB and Bitcoin RGB are twins, not one id.

R2 TRANSFER
Move the seal

Peel the sticker onto a new box. Broadcast a Liquid or Bitcoin tx that carries the stamp.

R3 CONSIGN
Hand the envelope

Off-chain consignment: history + which box + how to check. No envelope, no proof of ownership.

R4 VERIFY
Check it yourself

Seal closed? Stamp matches? Shareable proof page. Third party needs no keys.

4 · What this lab will not confuse

RGB contract — off-chain consignment + client verify. This is the product claim.

Native Liquid asset — LWK issue_asset. Fees and backing only. Not an rgb: id.

BFA mint-gate — cannot mint more stickers than the vault holds. Audit rebuilds history with no oracle.

No teleport — a contract cannot hop chains. Cross-chain means swap twins.

No browser wallet — public Cloud Run is GET-only. T1 demo swaps are off unless flagged.

No mainnet — Liquid Testnet + Bitcoin testnet. Live site: rgbmvp-public on Cloud Run.
